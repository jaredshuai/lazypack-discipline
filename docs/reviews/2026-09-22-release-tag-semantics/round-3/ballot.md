## 候选条文骨架（供对照，非投票项）

三席终稿的共同骨架：S1 分层句 → 意图句 + S2 → §5.4 关系句 → 标签锚定句 → 否定句 → 末句项目层委托清单。以下逐项决定骨架内的变体。

## B1 段名

- **A**：保留「平台段」，不改名（grok、qoder 第二轮终态）
- **B**：统一改名「项目段」，同批改 `DECISIONS.md:66`/`:84` 与快照（devin 第二轮终态）

## B2 意图句锚点

- **A**：不写本机/云端锚点——「是否构成发版，按发布意图区分，不按执行地点区分；生成构建产物不自动构成发版。」（grok、qoder）
- **B**：写双锚点——「是否构成发版按发布意图认定，不按执行地点或构建产物的存在推定：本机执行的正式发布是发版，云端产出的测试包可以不是发版。生成构建产物不自动构成发版。」（devin）

## B3 §5.4 关系句措辞

- **A**：指针收窄版——「版本号升位与不触发版本发版的提交类型依 §5.4，§5.4 不认定发布是否达成。」（qoder）
- **B**：完整版——「§5.4 仍决定发版时版本号如何升，以及哪些提交类型不触发版本发版；它不表示单次提交或单次构建已经完成上传或交付。」（grok）
- **C**：devin 版——「§5.4 决定发版时的版本升位与哪些提交类型不触发发版，不代表单次提交或单次构建的发版已完成。」

## B4 标签锚定措辞

- **A**：「每次发版须以 Git 版本标签标识产生该发布物的提交」（qoder、devin）
- **B**：「每次发版须用 Git 版本标签标识被发布的提交……该次发版若含构建产物，产物须由该提交产生」（grok）

- **B**：不加（devin 终稿未含）

## B6 已推送标签不可移动

## B7 否定句措辞

- **A**：「标签存在不证明该次发版已完成」（devin）

## B8 重复发版 / 分渠道
