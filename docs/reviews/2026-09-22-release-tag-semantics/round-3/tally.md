## 三、多数条文的合并组装（呈维护者裁定的 §5.7 候选全文）

按 §一 多数结果逐句组装；两处合并请求（B3 句尾、B6 削权）三席实质同向、且均采用在场席位第二轮已写出的文字，主持人予以采纳：

> **5.7** 打包上传属项目层，写在 `RELEASE.md` 固定段之外的平台段。是否构成发版，按发布意图区分，不按执行地点区分；生成构建产物不自动构成发版。版本号升位与不触发版本发版的提交类型依 §5.4；它不表示单次提交或单次构建已经完成上传或交付。每次发版须用 Git 版本标签标识被发布的提交，标签所标版本号遵循 §5.3；该次发版若含构建产物，产物须由该提交产生。已推送的版本标签不得复用同一版本号于其他提交，移动亦须显式授权；同一提交的再次上传或分渠道发布，不因此要求新的版本标签。版本标签的存在不证明项目层所写的上传或交付已经完成。本项目以哪个动作表达发布意图、上传或交付如何算完成、再次上传或分渠道发布如何标注、标签由谁创建、是否推送，以及标签与构建、上传和 CI 的先后，由项目层在平台段规定。

逐句与票项对应：

1. S1 分层句——B1-A，「平台段」保留（grok 二轮版「固定段之外的平台段」）。
2. 意图句＋S2——B2-A（grok 句式，无地点锚点）。
3. §5.4 关系句——B3-A 前半＋B 句尾（qoder 合并案）：只留指针不复述 §5.4 职能，句尾否定对象落在「上传或交付」而非「发布达成」，避免把「完成」挂回发版（grok §2.1 警告的形状）。
4. 标签锚定句——B4-B＋B5-A（grok 二轮原句）。
5. 不可移动/复用＋重发豁免——B6-A 按 qoder 削权＋B8-A（qoder 三轮合并写法的两句）：「不得复用」为硬禁令，「移动」保留但须显式授权（给误标补救留路径）；B8-A 与 B6-A 闭环，消除 force-move 诱因。
6. 否定句——B7 方向，文字采 grok 二轮：「已经完成」，不用「已成功」，不把「完成」安在「发版」上。
7. 末句委托清单——grok 二轮版（发布意图动作、完成判据、再上传标注、创建者、是否推送、先后关系归项目层平台段）。
