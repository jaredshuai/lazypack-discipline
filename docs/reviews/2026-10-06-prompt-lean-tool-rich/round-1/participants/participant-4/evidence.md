## 2. 关键论证步骤（观点的推导链）

### 2.1 为什么要补「可判定性」轴

草案判据：违反须强制 → 工具层。反例构造（用于检验，非实际规则）：

1. 设规则 R = 「可测层行为改动必须配套断言」（§6.5 确有此条）。
2. R 要求强制后果（无断言应阻止合入）——按草案应整体进工具层。
3. 但「本次 diff 是否含行为改动」「断言是否有效」均不可可靠机器判定（本仓已有变异测试基础设施正是为逼近「断言有效性」，仍须人工豁免流程，见 `docs/quality-gates/mutation-testing.md` 登记行）。
4. 若草案无第二轴，执行者面对 R 只有两条路：谎称可工具化（虚假闸门），或宣布无法工具化并把 R 整体留在提示词——后者恰好是草案要消除的失效模式。
5. 补第二轴后，R 的合法归宿清晰：可判定子规则（如「无测试文件时阻断」）进闸门，语义部分进 §6.3 审查通道，由 §6.4 对抗性双跑压低漏检。这正是 11.2 的内容。

结论：第二轴不是美化，是防止草案在自身主战场上失效。

### 2.2 为什么「提示词层」必须拆分

草案把「仅提示或人工审查判断」的规则统称为「提示词层」。但固定层已把散文分成两个家：

- 常驻文件（§4.1 末行：指针 + 每会话必踩，一屏为限）；
- 按需文档（§4.1：`CODING_STANDARDS.md` 审查时执行；`docs/agents/<主题>.md` 按需读取）。

「人工审查判断」的规则按 §6.3 的合法家是 `CODING_STANDARDS.md`，不是常驻文件。若草案不拆分，会产生两种误读：
- 误读 A：凡不强制者皆可堆进 AGENTS.md —— 直接违背 §4.1 一屏约束，加剧 Lost in the Middle；
- 误读 B：凡不强制者皆为「提示词」，审查通道被忽视 —— 违背 §6.3/§6.4。

11.1/11.2/11.3 的三目的地（工具配置或 CI / 按需散文 / 常驻文件）即由此推出。

### 2.3 为什么保留清单必须含「指针」

- §4.1 末行明文：AGENTS.md = 指针 + 每会话必踩的几条。指针是常驻文件的首要职能；
- 本仓 AGENTS.md（9 行纯指针）与 setup 生成模板（指针占位符 + 双角色门禁明文）均以指针为主体；
- 草案列举的三类（角色边界、文档归属、多 AI 协作协议）全是「约定」，不含路由信息。若按草案字面执行，瘦身后的 AGENTS.md 会失去「去哪读什么」的职能，反而迫使规则正文回填常驻文件。

### 2.4 为什么「角色边界」列在无法工具化侧但仍需说明理由

- 路径 × 角色写权限矩阵在技术上可检查（hook 可按路径拦写）；
- 但 hook 无法获知当前会话自报的角色身份，矩阵无输入；
- 故归「须强制 + 不可可靠判定」，由 11.2 通道（审查 + 对抗性双跑）承担。
- 若未来宿主提供角色感知能力，该归类可复审——已在 result §1b 注明，避免条文被读成永久断言。

### 2.5 章节归属的排除法

- 并入 §6：§6 的操作内容是「提交前跑哪四个闸门」，本条是「所有规则的载体分配」，域包含 §6 而非被包含；并入会使 §7.5 类诚实条款的归属失去依据。
- 并入 §4：§4 登记表的对象是文档/产物（含生命周期），本条对象是「规则」；混表会破坏 §4.1「一个东西只有一个家」的同构性。
- 新 §11：扁平编号追加，不改既有条号；模板头注 `src=DECISIONS.md@x.y.z` 与 skill 内的 §4/§5/§6 引用零改动。放置文末另有一个自我指涉的好处：按议题引用的 U 型注意力证据，文末是高注意力位。

## 4. 待裁决的边界情况

1. **高假阳性检测器的中间态**：能检测但假阳性偏高的规则（如文档关系检查的某些对子）不配做阻断闸门，又强于纯提示。建议「CI 警告 + 审查者必核」的中间态是否写入 11.1/11.2 之间，或留项目层自行掌握——草案与本人替代文本均未覆盖，提请第二轮讨论。
2. **本仓自身是否示范接线**：`check_commit_msg.mjs`/`check_doc_pairs.mjs` 均已存在且可判定（F3），按本条精神应接闸门；但接线属项目层决定（§2.2），且本仓登记册明示其「不是门禁」。本仓作为固定层来源仓是否应承担示范义务，提请维护者裁定。本人不主张随本条捆绑强制接线，避免把载体原则扩张成接线义务。
3. **「角色边界」的工具化复审触发**：若宿主未来支持角色感知 hook，11.3 中该示例的归类应复审（见 2.4）。无需本轮裁决，记录在案。
4. **检测 ≠ 自动修复的显式化**：草案背景把「不好自动修复」与「不好工具化」并提（提示词 §1a 文档同步例）。本人观点：闸门只要求可靠检测，修复始终由人做；建议在条文或第二轮互评中显式消除「工具化 = 自动修复」的潜在误读。可在 11.1 后补半句「工具层只要求可靠判定与阻断，不要求自动修复」，是否采纳提请第二轮。
