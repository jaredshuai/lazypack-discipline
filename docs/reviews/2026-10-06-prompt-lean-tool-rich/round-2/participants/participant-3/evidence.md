## 2. 核心推理链

### 2.1 推理链 1：因果倒置纠正 $\to$ 三轴分离模型
```
草案原逻辑：
  [管理意图: 必须产生强制后果] ──(倒置分类)──> [划入工具层]
  缺陷: 无法由机器可靠判定的业务规则若被要求强制，将无工具可用而悬空；
        已有机器检测但未接闸门的检查器被错误开除出工具层。

本人第一轮纠正:
  [规则内在属性: 确定性判定逻辑] ──(技术决定)──> [划分执行载体]

第二轮融合 P1 三轴框架:
  ┌─ 轴 ①: 规则声明源 (唯一权威正文，居 DECISIONS / CODING_STANDARDS)
  ├─ 轴 ②: 载体分配 (可判定性优先: 机械归工具，语义归审查者)
  └─ 轴 ③: 治理部署 (接线授权: 阻止提交/合并需另行授权；未接线仍属工具层)
```

### 2.2 推理链 2：常驻入口指针化 $\to$ 声明与执行分离（口径住条文）
```
草案原意:
  规则迁入工具配置 ──(误读)──> 在 linter/hook 配置中重新抄录规则
  后果: 制造配置与条文的双事实源，违反 §1.4 和 §4.1。

收敛后的正统模型:
  1. 权威口径 (条文/规范正文) ──[运行时抽取/读取]──> 2. 确定性工具 (执行器)
          ▲
          │ [导航指针]
  3. 常驻入口 (AGENTS.md)
  
  效果:
  - AGENTS.md 仅保留指针 (瘦，不占用上下文)
  - 规则口径唯一定义在条文 (一处一条)
  - 工具作为外部执行器承担机器计算 (工具肥)
```

### 2.3 推理链 3：新 §11 与 §1.4 的辩证统一
```
现状:
  §6.1 (散落半句) ──┐
  §6.3 (散落半句) ──┼──> 缺乏上位总纲，分散存在 (不稳定的局部事实)
  §4.1 表 (散落条目) ┘

方案 A (新 §11 + 连带修剪):
  设立 §11 (载体三轴分离总纲) 
     ▲
     ├── §6.3 修改为指向 §11
     ├── §4.1 修改为指向 §11
     └── §6.1 顺延为下位特例
  结论: 1 个权威定义 + 2 处指引，消除冗余，符合 §1.4。

方案 B (硬并入 §6.6):
  §6 标题为“质量门禁”，但 AGENTS.md 裁剪并非门禁，导致 §6 概念溢出；
  且 §4 表依然无法干净引用。
```

### 2.4 推理链 4：门禁总触发令与接线授权的互锁机制
```
  [物理环境层] ── P1 轴 ③ (接线授权):
    工具是否挂载在 git pre-commit / CI 流程上。
    
  [会话行为层] ── P3 门禁总触发令 (§6.4):
    Agent 在会话中是否主动运行门禁。
    
  互锁场景:
    场景 A (已接线): Hook 自动阻断，但 Agent 依然需要前置运行门禁以避免提交失败回滚。
    场景 B (未接线/第四态): Hook 不存在！此时若无常驻入口的“总触发令”，
           Agent 绝不会自发运行检查器，工具完全沉睡。
    因此，常驻入口中的门禁总触发令是激活工具层的终极开关。
```

## 5. Lost in the Middle 论证的更新与深化

### 5.1 辩证吸收 P1 的反思
- P1 在其 `result.md` §1(S4) 中指出：本仓 `AGENTS.md` 仅 9 行（799 字节），并不存在物理超长痛点；真正的注意力消耗在于指针展开后读取的巨型文档（如 `ARTIFACTS.md` 达 238 KB）。
- 本席完全采纳这一事实观察。

### 5.2 论证深化
1. **常驻入口瘦身不仅是防膨胀，更是防“扇出失控”**：常驻入口保持极简指针，能够确保 Agent 在会话伊始的注意力最高点（U 型曲线头部）准确锁定最重要的几条底线契约（门禁令、诚实底线）。
2. **“工具肥”本质上是对抗长文本遗忘的最强解药**：
   - 规则留在文档中，无论如何排版，一旦进入 LLM 上下文，其召回概率受长度影响均呈 U 型衰减；
   - 规则下沉到确定性程序（Linter/Script），其执行开销对 LLM 上下文而言是 **0 Token 消耗、100% 召回确定性**；
   - 这从根本上跳出了上下文注意力机制的物理局限，是“确定性机器兜底大模型概率缺陷”的最高体现。
