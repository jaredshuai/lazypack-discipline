## 3. 推理链（本轮四条主链）

### 链 1：越域承认 → 按域拆分 → 用「一处一条」代替「章号之争」
1. 第一轮我的文本主张落 §6.6，但 §5.1 拟文同时（a）改 §4 表 `AGENTS.md` 行、（b）新增 §4 表一行、（c）改 §6.3——即我自己给了三类对象：常驻内容边界、产物之家、门禁散文。
2. R1（P5）与 R6（P4）都指向日程语义域外溢。既然外溢成立，「必须放 §6」不成立。
3. 但「元规则 → 文末新章」也不是唯一出路：横切规则在本仓的既有归宿是 §1（§1.3/§1.4 均是横切，见 `DECISIONS.md:14-15`）。所以拆出第三条落点候选 §1.5，用 R6 自己的前提（域包含 §6）+ P3 自己的前提（与 §1 呼应）推出。
4. 既然三种落点都能承载同一判据，真正的分歧只剩「§1.4 是否被满足」。故把验收条件写成 C1（复述归零）/C2（域不越界）/C3（口径条款），把章号交维护者——这是 §9.3「僵局交裁」的正路，也保住 5/5 的判据不被 B5 连带否掉。

### 链 2：轴的问题不是几根轴，而是「分类 / 义务 / 授权」三件事被压成一句
1. 草案句 2 同时说了三件事：谁判定（能力）、要不要阻断（处置）、有没有接（状态）。
2. R13（warning）、R14/R15（P3 自证「接线状态差异」）、本席第一轮 S2 反例（`check_*` 存在但未接）分别击穿其中一件。
3. R3 补上第四个缺陷：句式可描述式读，则判据对现状永远为真、失去改革力。修法是把处置那一件**移出分类句**、写成义务句（R11 的 11.2 就是这句的成品）。
4. 于是「三轴 vs 两轴 vs 单轴」的表层分歧消解：单轴（判定）+ 义务句（处置）+ 授权与报告（状态）。P4 取得义务句、P5 取得稳态、P1/P2 取得授权边界、P3 取得「判定机制决定归属」。四人各自的核心诉求都能在同一句序里落位，故本轮判据可冲 5/5。

### 链 3：从「抽象两层」到「本仓已有两种现成范式」
1. 第一轮我用 §5.1 词表抽取一个例子讲「口径层与执行层分离」，P2/P3/P5 未被推动（他们按传统理解「迁入 = 抄进 biome.json」）。
2. 本轮取证发现体系里有两个更强、且各席已各自引用过的现成物：编译派生（`DECISIONS.md:6` + `src=DECISIONS.md@0.4.0` + P1/P2/P3 机检同源）与运行时抽取（`commit-msg-check.md:19/37`）。
3. 归纳出可判定标准：**被机器绑定同源的副本 = 派生（合法）；人手抄的副本 = 第二源（§1.4 违规）**。这条既解释为什么 setup 生成 `CODING_STANDARDS.md` 不算复述，也解释为什么把 type 抄进 lint 配置算。
4. 由此自答第一轮待裁项 1：§6.3 管派生文档的去重，① 管源的不动，二者对象不同，不冲突（R21 同向）。

### 链 4：§4 新增行的主张被实证否证一半
1. 第一轮论证：§4.3「册上查不到=未登记」→ 迁入工具配置无目的地 → 必须新增行。
2. 本轮核对 `docs/ARTIFACTS.md:45/49/51/54-57`：本仓已把 `scripts/check_*.mjs`、`scripts/handoff_*.js`、setup 的 `scripts/doc_*.mjs` 登记在类别「本仓执行辅助 / setup 执行辅助」下，状态 `current`，依据栏写明手动运行、未接 hook/CI。即登记册机制**已能**为工具脚本给家，且未因此产生 §4.3 争议。
3. R9（P3/P4）因此成立：固定层 §4.1 不必新增大类。
4. 但目标项目侧仍有缺口：§4.1 表若完全不提工具配置，接入项目把 lint 规则迁入 `biome.json` 时，「家」的判断只靠项目层自造类别，与 §4「一个东西只有一个家」的可执行性下降。故退让形式：条文**写明归属 §2.2 + 登记由项目层类别承担**（行或句皆可），不再坚持必须是表行。
