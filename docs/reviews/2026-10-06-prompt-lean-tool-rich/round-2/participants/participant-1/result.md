### 1.2 判据结构

#### 1.2.1 与 P2/P5「单轴 + 独立报告」的实质差异，以及能否融合

**与 P2：没有实质差异，本席撤回第一轮的区分。** 我原以为差异在「未接线要不要一道授权闸门」，P2 只给了事后如实报告。核对文本后：

- P2 在 result.md §3.c 写「若维护者裁定需要生成，**应另开实施票**并同步改写 `tool-or-user` 原则，**不在本次条文修订里隐含通过**」——这就是我的第三轴（接线另票），只是没有命名。

所以差异是**措辞层级**：P2 把授权写成事实报告的主语，我写成动作的前置。融合句：接线须有实施票与用户授权（前置），未接线/不适用/运行失败须按事实报告、不得宣称门禁已生效（后置）。两句都是我的 ③，且 P2 已给全。

**与 P5：一处实质差异。** P5 在其 result.md §5 写的 4.5 首句「迁移**以能实际接线为前提**」有反向风险：把接线当迁移前提，则无 CI、离线或工具匮乏的项目得出「规则不得迁入工具」的结论，恰好把 P5 自己想防的常驻膨胀留下（P5 自己在句 5 也承认「CI 可用性因平台而异」）。前提应当是**可判定 + 口径不迁出**，接线只决定报告状态。

**第四态（P5 句 2 末、P5 result.md §7 待裁项 2）**：我采纳，但把它重新定位——它不是第三条轴的结果，而是 ②＋③ 分离后的**必然产物**：机械可判（②判为工具层）+ 未获接线授权（③不阻断）= 手动运行的检查器。【事实】这正是本仓现状：`docs/ARTIFACTS.md:49`、`:51` 把 `check_doc_pairs.mjs`、`check_commit_msg.mjs` 登记为类别「本仓执行辅助」，依据栏均写明手动运行、未接 hook/CI。换言之，我第一轮提的第三轴与 P5 提的第四态是**同一件事的两种命名**；采纳 P5 的命名（更贴近读者），保留我的授权边界（更贴近 §2.2 与 `docs/agents/freshness-check.md:68`）。

### 1.3 「迁入」含义

#### 1.3.1 与 P4 的共识能否作第二轮基础共识

**能，但要先修 P4 自己的文本。** P4 result.md §4 的 11.1 写「须强制且可判定的规则，**正文写进确定性工具**（lint、格式化、类型检查、测试、提交前 hook、CI 闸门），不另留散文复述」。这句按字面执行即「把 §5.1 的 8 个 type + `chore`/`revert` 抄进 lint 配置」，正是本席第一轮 §1-S2 与 P4 evidence.md §2.2 都反对的双源。P4 的立场与 P4 的措辞冲突。

交给 P4 的修法（一句话替换，不动其框架）：「正文写进确定性工具」→「**判定接入确定性工具，口径仍以该规则的唯一权威正文为源**」。这样 P1/P4 的共识才真正落到可投票文本上。

#### 1.3.2 如何向 P2/P3/P5 解释「口径声明层与执行层分离」的必要性

第一轮我讲的是抽象两层，说服力不足。本轮换成一个 P2/P3/P5 各自已引用的**具体现成物**：

1. **编译器已经在做这件事。**【事实】`docs/DECISIONS.md:6` 导语规定项目层文件由 `/lazypack-setup` 从固定层**编译得出**，出现分歧以固定层为准；`resident-entry.md:1-4`、`CODING_STANDARDS.md:1-3` 的受管块带 `src=DECISIONS.md@0.4.0` 与来源内容标识。即：**同一口径可以同时存在于源与派生载体，只要派生是被机器绑定同源的**（P1 字节 SHA-256、P2 git blob、P3 版本串，本席实跑 6/6 PASS）。
2. **口径抽取是同一范式的第二种实现。**【事实】`docs/agents/commit-msg-check.md:19`、`:21-22`（`--rules` 只切换哪份文件供词表）、`:37`（抽取走不通即 `exec-failed`，不回落内置清单）。
3. **推论**：「迁入工具配置」的合法形态只有两种——工具**运行时读条文**，或由编译器**派生**并机检同源。第三种「人手把口径抄进配置」在本体系里是 §1.4 与 §4.1 的双源，且没有任何机检能发现它漂移。这就是必须钉住的原因：不是概念洁癖，是漂移无人看守。
4. **这同时消解本席第一轮待裁项 1**（§6.6① 是否与 §6.3 在 `CODING_STANDARDS.md` 上冲突）：**不冲突**。§6.3（`docs/DECISIONS.md:91`）管的是**派生的标准文档**里不该重复工具已判定的条目；① 管的是**源**不得从条文搬进配置。两句作用对象不同、方向不同，不构成对同一对象的相反指令。P2 在其 result.md §4 改写 6.3 的做法（「按 6.1(c) 切分后，工具已判定的条目从本文件删除」）与此一致，可作统一措辞。
