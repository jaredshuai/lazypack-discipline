# 草案 A 修正稿：§4.1 文档二分判据

> 基于第二轮评估修改，2026-10-08

## 修改依据

### 第二轮发现的缺陷
1. **判据自相矛盾**（P1/P5）：判据段说"临时交接"是过程稿，但交接文档有下游消费者
2. **"沉淀前不得丢弃"不可验收**（P1/P2/P3）：丢弃动作销毁证据本身
3. **表述内部冲突**（P1/P2/P5）：判据段说"不占本表的家"，但刚把 `.scratch/` 写进本表

### 维护者裁定
- Q1：ARTIFACTS 登记粒度 = 目录级一行
- 影响：判据需支持"路径或其父路径"匹配

---

## 修正后条文

**位置**：§4.1 表下，作为"读表判据"小节

### § 4.1 表（保持不变，仅修订 `.scratch/` 行）

| 东西 | 家 | 何时清 |
|---|---|---|
| 临时现场与运行时缓存 | `.scratch/<feature>/`，默认不进版控 | 票关闭且验证交付后，经四步清理关卡安全回收；回收前须逐项写明去向 |

**修订说明**：
- 补"默认不进版控"（P5 建议）
- "沉淀前不得丢弃"改为"回收前须逐项写明去向"（P1 建议）

### § 4.1 读表判据（新增）

本表分两类文档：

1. **跟改型**：有下游消费者持续依赖的权威原件
   - 判据：§4.3 在册项、工单验收标准或提交 `Refs`/`Closes` trailer 指向了这个路径或其父路径
   - 例：词汇表、ADR、登记册、接口契约、编码标准
   - 约束：按 §7.1 跟改；一个事实只有一个家（§4.1 原则）

2. **过程稿**：辅助当前实现、用完即弃的临时交接
   - 判据：未被 §4.3 在册项、工单验收标准或提交 trailer 引用
   - 例：需求草稿、AI 生成的规划文档、会话交接文档、讨论记录
   - 约束：不占跟改型的家；回收前须逐项写明去向（ADR 编号/工单号/登记册行/纯噪声）

**反向对子**（防逃逸）：
- `.scratch/` 内文件被 §4.3 在册项、工单验收标准或提交 trailer 引用 → 视为落位逃逸，须迁出 `.scratch/` 或登记为跟改型

**检查点**：
- 审查者（§6.4）在工单关闭前检查：过程稿是否已写明去向，跟改型是否已同步更新

## 与现有条文的关系

**补充关系**：
- 补充 §4.1 原则"一个事实只有一个家"的执行判据
- 补充 §4.3"册上查不到的产物视为未登记"的反向规则（什么不占册）

**不冲突**：
- §4.1 原则仍然成立，只是明确了"家"的两种类型
- §4.3 仍然是"查不到 = 未登记"，判据只是补充"什么该查到"

**衔接 §7**：
- 跟改型按 §7.1 跟改
- 过程稿不受 §7.1 约束，但受 §3.4 清道夫四步清理关卡约束

## 验收标准

**可机检部分**（将来接入工具）：
- 检查 `.scratch/` 是否在 `.gitignore`（若不在，warning）
- 检查提交是否引用了 `.scratch/` 路径（若引用，报警要求迁出或登记）

**人工审查部分**（§6.4）：
- 工单关闭前，审查者检查：过程稿去向是否已写明（ADR/工单/登记册/纯噪声）
- 工单关闭前，审查者检查：跟改型是否已同步更新

## 示例

### 示例 1：需求草稿用完即丢
```
# 工单 #123 验收检查表
- [x] 功能实现
- [x] 测试通过
- [x] 文档同步：
  - [x] `.scratch/feature-x/需求草稿.md` → 纯噪声（已提取到 ADR-045）
  - [x] CONTEXT.md 补充"特性X"词条
```

### 示例 2：交接文档用完即丢
```
# 工单 #124 验收检查表
- [x] 功能实现
- [x] 测试通过
- [x] 文档同步：
  - [x] 系统临时目录交接文档 → 已删除（仅服务本票实现）
```

### 示例 3：逃逸被捕获
```
# 审查者检查
提交 abc123 的 trailer 包含：
Refs docs/work/feature-x/spec.md

但 `docs/work/feature-x/spec.md` 未在 ARTIFACTS.md 登记。

要求：
- 选项 A：迁移到标准路径并登记（如 docs/specs/feature-x.md）
- 选项 B：在 ARTIFACTS.md Section 3 登记为非标路径
```
