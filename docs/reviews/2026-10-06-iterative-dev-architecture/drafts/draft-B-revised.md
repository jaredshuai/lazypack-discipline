# 草案 B 修正稿：§7.7 跨票据结构复盘

> 基于第二轮评估修改，2026-10-08

## 修改依据

### 第二轮发现的缺陷
1. **"一批票"无锚点**（5/5 独立发现）：最省事的合规读法是"每票=一批"，被否决的每轮复盘从后门回来
2. **执行主体"或"稀释责任**（P1/P2/P5）："规划者或书记员"意味着两个角色都可以不做
3. **三态结构错误**（P2/P5）：① 无偏移、② 有偏移是结论态，③ 禁止是禁令，不是第三种状态
4. **① 态不可验收，且缺 §7.3/§7.4 指向**（P1/P2）：① 明写"不产出文档"，即合法稳态在版控中零痕迹

### 维护者裁定
- Q1：ARTIFACTS 登记粒度 = 目录级一行，影响 ② 态的"文档有变动"判据
- Q3：批次锚点 = `Closes` 事件或发版前

## 修正后条文

**位置**：§7.7（新增），在 §7.6 之后

### § 7.7 跨票据结构复盘

**触发时机**：每张票以 `Closes` 收束后，或发版前

**执行**：
1. **规划者**判断：本次收束的 diff 是否让代码结构与架构文档产生偏移
2. **书记员**在既有扫描（§3.4）中核对：规划者结论是否在版控中留痕

**两种结论**：

① **无偏移**：模块拆分、依赖关系与架构文档仍对齐
   - 本条不产出文档，属不可验收的教学性表述
   - 条文重量全压在 ② 的对子上

② **有偏移**：diff 走向与 ADR、CONTEXT、ARTIFACTS 登记的结构发生实质背离
   - 须触发下列至少一项（存在性对子）：
     - 文档同步：ADR 或 CONTEXT 有变动（含 ARTIFACTS 登记路径下的文件），按 §7.3 写明取代关系或按 §7.4 三条件写新 ADR
     - 处置票：开票记录偏移原因、决策、后续调整方案，票号出现在提交 trailer
     - 登记更新：ARTIFACTS.md 新增或修订登记行，反映结构变化
   - 退出条件：`git diff` 涉及对应文档/ADR 路径、处置票存在、ARTIFACTS 有变动，三者有一即通过

**两条禁止**：

③ **禁止补写已复盘记录**：
   - 复盘结论已落 ADR/处置票/登记行后，禁止事后补写"其实当时就发现了"
   - 目的：防形式主义，逼复盘前置

④ **禁止绕过 ADR 直接改登记**：
   - ARTIFACTS 行的状态变更（current → superseded）必须对应 ADR 取代关系（§7.3）
   - 架构决策的家是 ADR，不是登记册

**配套工具**（降低复盘成本，项目层按需启用）：
- 架构可视化：UML 依赖图逐层下钻
- 依赖合规检查：dependency-cruiser 之类，机器报违规、人做判断

## 与现有条文的关系

**落点**：§7（4/5 共识）
- 本质是"代码事实与文档对齐"，属 §7.2 对子家族
- 与 §7.1 主路并行：规划者边问边写（前置），关票后复盘（后验）

**衔接关系**：
- 触发 §7.3 取代关系：有偏移时，新决议按 §7.3 写明取代哪条
- 触发 §7.4 三条件：难逆转、没上下文会奇怪、真有取舍 → 写新 ADR
- 触发 §4.1 跟改：偏移结论要落到跟改型文档（ADR/CONTEXT/ARTIFACTS）
- 书记员扫描（§3.4）包含本条的核对

**不与 §3.4 发版前重叠**：
- §3.4 书记员"发版前或按需扫一遍"
- §7.7 触发点是"`Closes` 或发版前"
- 发版前同时触发，但 §7.7 聚焦结构偏移，§3.4 聚焦全局文档补全

## 验收标准

**可机检部分**（将来接入工具）：
- ② 态退出条件：检查是否存在文档变动、处置票、ARTIFACTS 变动
- ③ 禁止：检查 ADR/处置票的提交时间是否早于对应功能提交
- ④ 禁止：检查 ARTIFACTS 状态变更是否对应 ADR 取代关系

**人工审查部分**（§6.4）：
- 规划者在关票前判断：本次 diff 是否让结构偏移
- 书记员在扫描时核对：规划者结论是否留痕

## 示例

### 示例 1：无偏移（① 态）
```
# 工单 #125 复盘
规划者判断：
- 新增 `utils/formatDate.ts`，未改变模块划分
- 依赖关系无变化
- 结论：无偏移

书记员核对：
- 提交 abc123 无 ADR 变动
- ARTIFACTS.md 无变动
- 无处置票
- 通过（① 态在版控中零痕迹，合法）
```

### 示例 2：有偏移，文档同步（② 态）
```
# 工单 #126 复盘
规划者判断：
- 新增 `core/auth/`，但 ADR-012 记录认证逻辑在 `services/`
- 结论：有偏移

处置：
- 提交 def456 更新 ADR-012：认证逻辑迁移到 `core/auth/`（按 §7.3 写明取代关系）
- 提交 def456 更新 ARTIFACTS.md：登记 `core/auth/` 为 current

书记员核对：
- `git diff def456` 涉及 `docs/adr/012-*.md` 和 `docs/ARTIFACTS.md`
- 通过（② 态对子满足）
```

### 示例 3：有偏移，开处置票（② 态）
```
# 工单 #127 复盘
规划者判断：
- 新增 `ui/components/legacy/`，但架构已约定不再扩展 legacy
- 结论：有偏移

处置：
- 开票 #128：记录偏移原因（历史包袱）、决策（暂时保留）、后续调整方案（迁移到新组件）
- 提交 ghi789 的 trailer：`Refs #128`

书记员核对：
- 处置票 #128 存在
- 通过（② 态对子满足）
```

### 示例 4：违反 ③ 禁止
```
# 审查者检查
工单 #129 关闭时无 ADR 变动。

三个月后，发现架构偏移，补写 ADR-050：
> 2026-07-15：#129 实现时已发现模块拆分不合理……

违反：③ 禁止补写已复盘记录

处理：
- ADR-050 删除回溯性表述
- 改为：2026-10-08 发现历史遗留结构问题……
```

### 示例 5：违反 ④ 禁止
```
# 审查者检查
提交 jkl012 修改 ARTIFACTS.md：
- `docs/specs/old-api.md` 状态：current → superseded

但无对应 ADR 取代关系。

违反：④ 禁止绕过 ADR 直接改登记

处理：
- 要求先写 ADR（按 §7.3 写明新 API 取代旧 API）
- 然后再改 ARTIFACTS.md 状态
```

## 与 §6.5 质量双轨的关系

**互补，不重叠**：
- §6.5 关注单次提交的测试覆盖（横向：这次改动是否有断言）
- §7.7 关注跨票的结构对齐（纵向：积累的 diff 是否让结构走歪）

**共同目标**：防止架构腐化
