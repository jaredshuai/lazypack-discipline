## E1. 草案 A：判据的反例推演

**核心反例：§4.1 表自带的「交接文档 → 系统临时目录，用完即弃」。**
交接文档的存在意义就是被下游消费者（下一会话的 agent）读取并据其行动——它是「承载下游依赖」的标准样本。按草案判据字面（承载者属登记册、须跟改），交接文档应判进登记册；但草案同一段把它列为过程稿例子，§4.1 现行行也规定其用完即弃。判据在自举样例上即失效。

**真正的分野维度**（备选表述，供修改参考，非裁定）：
- 依赖的**持续性**：交接的依赖在消费后立即终止（读完即死）；规格/ADR 的依赖持续有效且失效后会误导——「它过时了会不会让人做错决定」（P1 测试）比「有没有下游依赖」更能切对位置。
- 依赖的**时间界**：同会话内 planner→executor 的接力是「本次生成链内消费」，不是跨生命周期的下游依赖。「仅服务本次生成」这一限定必须进判据段本身，不能只留在表格行。

**「不进版控」缺失的推演链**：#41 的诉求是过程稿不进版控 → 草案行的家是 `.scratch/<feature>/` → `.scratch/` 位于仓内 → 除非项目层 gitignore 或条文写明「默认不进版控」，否则过程稿依然进版控 → 病灶保留。P2 第一轮 §一已独立指出同一缺口，草案未吸收。

**沉淀去向对比**：

| 文本 | 允许的家 |
|---|---|
| P0-1 裁定 | ADR、工单、登记册（三家） |
| 草案判据段 | 「属登记册」（一家） |

非文件载体（issue 评论、提交 trailer）无法进「登记册」语义——它们是 P1 三态留痕、P3 复盘声明、P4 显式声明的共同假设存放地，判据不管辖它们会留下口径裂缝。

**§4.3 替代方案检验**：§4.3 只定义「册上查不到即未登记」（检测规则），不定义「何时应登记」（义务判据）。缺口确实在判据，新增有正当性；但「降级须裁定」句是 §4.3 语义，合写进 §4.1 判据段属两条规则同居一处。

**四分未覆盖**：P1 第一轮已证 §4.1 实为四分（跟改/冻结/归档/用完即弃）。判据段「文档按…分型」字面是全称分型，冻结型与归档型会被误读为不存在或被错塞。建议判据段声明只管「在册义务边界」，不自称完整分型。

## E2. 草案 B：三处矛盾的展开

**「三态」计数错误**：①②是态，③是禁令。「三态之一」把禁令编成了第三个结果态，执行者读到③时无法回答「我现在处于哪一态」。应写「两态结果 + 一条禁令」。

**②③调和逻辑**（支持草案可成立的部分）：复盘是动作，ADR 是决策的家。②要求的是「决定按 §4.1 回家」——ADR 因 §7.4 三条全中而写，它的在场证明的是「有决定」，不是「复盘发生过」。③禁的是以「本次复盘无问题」式文档冒充复盘。语义上可调和；字面上「书面记录充当复盘」可把②的 ADR 也框进去，须把「复盘过程记录」与「决策记录」切开写。

**「一批」锚点的两种退化读法**：
- 紧读法：每票 `Closes` = 一批 → 等价于被否决的「每轮必复盘」；
- 松读法：仅发版前 → 书记员/清道夫发版前才有义务，跨票漂移积累期无人在看。
草案复用 §3.4「书记员在每张票关闭后扫一遍」与清道夫发版前两个既有锚点的意图明显，但「一批票以 Closes 收束后」把单票锚点写成了批次锚点，中间的批次声明机制（epic/标签/里程碑/连续 Closes 链）缺席。

**结构性不可见性（如实陈述而非缺陷）**：①零产物 + ③禁记录 → 「复盘发生过且结论无偏移」与「复盘根本没发生」在版控上不可区分。本条文的实际担保范围是：漂移发生而未留档 = 违规。对「没做复盘」无法担保。这是用不可见性换反形式主义，交换本身合理——我第一轮反对的是「装作可验收」，草案若如实写明担保范围，即不再是那种条文。

**对子的过触发面**：对子要求「改了边界 → 必须有文档/ADR 变动」。§7.4 的 ADR 门槛（难逆转+没上下文会奇怪+真有取舍）意味着存在合法情形：可逆、明显、无取舍的边界微调不够格进 ADR。此时对子逼出的「文档变动」只剩两类出路——写一份推导型模块图（撞 §4.1「能推出来的不手写」）或在工单留一行说明（须项目层定义对子时明确工单评论算合格出口）。属可修，非阻塞。

**落点 §7 vs §6**：§6.7（P3 案）的代价是「显式声明/签字」作为合规出口——这正是草案 B 用③杀掉的东西。放 §7 保住「零产物合法」的设计；放 §6 会把形式主义从侧门请回。角色上建议回到 P1 分工：规划者判（§3.1 架构判断归他），书记员核（§3.4 的扫已存在，加一项存在性核对即可）。

## E3. 草案 C：反对立场的修正与保留

**我第一轮反对的三个理由与两版草案的对应**：

| 第一轮反对 | V1 现状 | V2 现状 |
|---|---|---|
| 无度量单位 | 不再量大小，用功能测试兜底——单位问题被绕开而非解决（「一轮」仍可被声明成任意大小） | 同左 |
| 不可验收 | 「能指出哪条断言」可验但空洞——§6.5 已要求，边际约束为零 | 前半句同 V1；后半句双禁管动机，不可验 |
| 合理大迭代被误伤 | 不成立——可验收的大重构不违反 V1 | 同左（出口约束而非范围约束） |

**结论的修正**：对「大小上限」的反对不再适用于这两版（它们都不是大小约束）。保留的反对集中于两点：
1. V1 是同义反复——以「能指出验证」定义迭代，则「迭代结束时有验证」重述 §6.5，零净约束。空洞条文按「海盗法典」论证仍有成本：它让固定层出现一条永不触发也不被违反的字。
2. V2 双禁句的禁止对象是「理由」。版控、tracker、机器都验不了理由，只能验结果。把它写成固定层禁令，等于授权后续执行者互相指控动机——比无条文更坏。

**危害排序的依据**：V1 入 §2.4 的代价是一句不产生约束的定义——低害低值；V2 后半入固定层的代价是不可验禁令被工具化执行或习惯性忽略——高害。「若必须选一个」，选 V1，但须写明它是定义附注而非约束条文，且不宣称它承载了 #41 的「反重前置规划」——那一半在 V1 里根本不存在。

**未解决项**：反前置规划的落实点在澄清行为本身（`to-spec`/`grill` 的深度上限），属 skill 行为与 `docs/agents/` 指引，第一轮立场不变。
