# 参与者 1 第二轮评估：三个可合并草案的条文表述

> 参与者 1 - 实用主义工程师，第二轮，2026-10-08

本轮我仍然只问一个问题：**这句条文被违反时，能在版控或 tracker 里看见什么？** 看不见的那半，建议不要写成强制句。

材料边界：本轮只读 `round-2/prompts/common-v2.md`、`P0-rulings.md`、`round-1/participants/*` 与 `round-1/summary.md`。按独立性约束未读 0.6.0 正文与项目当前状态，故凡涉及"现有条文是否已覆盖"的判断一律标为待核对，不当作已证实。

---

## 草案 A 评估

**核心毛病：判据把"依赖"写成了意图，而不是可观察物。** "执行者、审查者按它验收"是关于内心的断言：同一个文件，两个执行者可以分型相反，机检无法复现。建议给一个入口判据——**有没有一个 §4.3 在册项、工单验收标准或提交 trailer 指向了这个路径**。有指向 = 登记册，无指向 = 过程稿。它不完美（会话内被读过但未留链接的消费者查不到），但把不可判的"谁依赖它"换成可判的"谁指向它"，漏判还能被下面的反向对子接住。"疑义时偏向登记册"须明写，否则判据本身成为争议源。

**"沉淀前不得丢弃"不可验收，原因是结构性的**：丢弃动作销毁的正是证据本身。文件已不在，"结论已沉淀"只能是声称，无反证路径。可救的是改成**动作前置条件**：「回收前须逐项写明去向（ADR 编号 / 工单号 / 登记册行 / 纯噪声）；去向不明者不得删除，原地保留提请裁定」。这句挂在"删除"这个动作上，在场性可查（§6.6②）；清道夫不能自证，应由书记员在 §3.4 扫描内核对该清单在场。

**在册降级只需裁定记录我可以接受，但"记录"须先给家**：无路径的裁定记录 = 口径无家（§6.6①）。应写死"工单评论 + ARTIFACTS 行变更，二者构成 §7.2 类对子"。

**钻空子路径不仅存在，A 恰好把它留在最顺手的位置**：执行者把应登记的规格写进 `.scratch/`，免 §7 跟改之外还能被合法删除（§3.4③ 的保护覆盖 `docs/work/` 与在册项，不覆盖 scratch）。必须补反向对子：「`.scratch/` 内文件被 §4.3 在册文档或工单验收标准引用 → 视为落位逃逸，须迁出或登记」。缺这一句，该行等于给逃避跟改开了一个有官方地址的通道。

**两处表述硬伤**：① 判据段把"临时交接"列为过程稿并说"不占本表的家"，而 §4.1 表本有「交接文档 → 系统临时目录」一行，自相矛盾，须择一；② P0-1 裁定写"不进版控"，A 的行写"经四步关卡回收"（隐含在仓内），口径未对齐。是否入 gitignore 属项目层（§2.2），固定层只写义务：「默认不入库；一旦入库即视为在册候选」。

## 草案 B 评估

**"一批"未定义，而"一批票收束"在版控里没有对应物**。1 张、3 张、10 张皆可自择：单位由被约束者自定，等于无约束——这是我第一轮"上限制造规避动机"的翻版。锚点其实现成：`Closes` 每次提交都可判（§5.1），"发版前"已挂在清道夫上（§3.4）。建议**删掉"一批"**，写「每张票以 `Closes` 收束后，或发版前」。P2 第一轮反对引入迭代单元的论证成立，B 的现表述却已把单位请了进来。

**三态中只有 ② 可验收**。① 明写"不产出文档"，即合法稳态在版控中**零痕迹**；于是"判定过且无偏移"与"什么都没做"外部不可区分。这不是措辞能修的，是"无产物 ⇒ 不可证"的逻辑必然。① 只能靠 ② 的漏网间接观测，条文重量必须全压在 ② 那句对子上；① 可保留，但应标注为反形式主义的教学性表述而非验收依据（§6.6②）。

**③ 与"如何证明判定已发生"确实互咬**：③ 禁止书面记录充当复盘，① 又禁止补写"已复盘"记录，则完全遵守 B 的外部表现就是"没有痕迹"——不可判定，且自指（这条禁令本身无法验收）。但 ③ 有可判的否定式改写：**不得新建以"复盘"为名的文档类；结构性结论只能进 ADR（受 §7.4 三条约束）或登记册状态行**。这句挂在路径与文档类型上，可机检，也接住我最担心的"每次复盘一份 md"；该不该进 ADR 仍由 §7.4 判。

**落点：§7**。B 比的是"文档/ADR 变动在场"，属跟改域。放 §6 会触发 §6.6③（违反是否阻止合并）；未接线时在 §6 挂门禁，等于 0.7.0 落地当天制造已知违规面。若维护者倾向 §6，须同票裁定"不阻止合并"。

**主语"规划者或书记员"是反模式**：§3.2 的防撞车边界里，"或"通常等于没人负责，且规划者由人执行，会使 ① 态在纯 AI 会话里默认无人触发。建议拆开——书记员做存在性核对（§3.4 扫描本就挂在该时点，零新增触发器），偏移的裁定权归规划者/维护者。另：本仓公开主体是 markdown、无依赖图可跑；项目层若长期定不出这对子，B 只落 ①（P5 的死条文风险）。建议对子进"未定项"，最低执行频率绑"发版前"。

## 草案 C 评估

**版本 1 更接近可验收**，也比它看起来更接近我第一轮的降级方案：尾句已把"大小"下沉项目层，真正在争的只剩要不要留那句抽象。它可判的那一支是"**能指出哪条断言**"——断言名与门禁命令都有可引用标识符，存在性与反向引用皆可查。但它把这句挂在"一轮迭代"上，而 0.6.0 中不存在这个单位（§6.5 的"迭代层"是覆盖率分层，与节奏无关）；落点又是 §2.4（项目层默认值的编译扩展机制），读起来像编译参数而非交付纪律。两处错位须先修。

**一个断言算不算闭环？按现表述算，而且是最省事的过关路径**：指向一条既有断言、不改任何测试即可"指出"。防钻空子只需补一句：**所指断言须在本票 diff 中新增，或由本票 diff 覆盖**。文档型票无断言可言，其闭环 = 登记行同步（§7.1），写进项目层对子。若纳入，落点建议 §6.5 或票字段口径，不要 §2.4。

**版本 2 的"可验收增量"没有任何可引用标识符**：谁验收、凭据住哪都未定义，结果就是执行者自判；"审查者按票复核"§6.4 已有，按 §1.4 属重述。但它的后半句反而有可判代理：**"禁止以'快速迭代'跳过需求澄清"对应一个可查事实——开工时那张票的验收标准字段为空**。所以建议拆开：可判的半句改写为「验收标准为空的票不得开工」（tracker 字段，可机检）；"以一次可验收增量为上限"删除。

**最终建议：部分修正第一轮意见，方向不变**。维持"上限不进固定层"——无度量单位，且设上限制造拆伪小需求的动机。但承认版本 1/2 各含一半可判内核，值得纳入：① 票须指向具体断言或门禁项，且由本票 diff 覆盖；② 验收标准为空不得开工。其余（节奏、粒度、"打磨到完美"的边界）降 `docs/agents/iteration-scope.md`。这比我第一轮"整条降级"多让出两句，也给 P2/P3/P4 落了可执行位置。

需主持人核对：现有 §3.1 / §7 是否已要求票带非空验收标准；若已覆盖，①②并入既有条文即可，不必新增（§1.4）。

## 总体建议

- **A：修改后通过。** 必改：入口判据改为引用关系；"沉淀前不得丢弃"改为回收前置条件；补 `.scratch/` 逃逸对子；去重"临时交接"、对齐版控义务。
- **B：修改后通过（须缩窄）。** 删"一批"改用 `Closes` 事件；重量压在 ② 对子、① 标注不可验收；③ 改为"不得新建复盘类文档"；书记员核对 + 规划者裁定；落 §7。
- **C：部分纳入 + 降级。** 上限句不入围；两句可判内核入围（须先核不与既有条文重复）。
- **需要更多信息**：三案共同前提 **ARTIFACTS 登记粒度**未裁，P0 未覆盖；采逐文件会令 `docs/reviews/**` 淹没反向引用，三案机检句同时失效。另需裁：`.scratch/` 版控义务、trailer 与 §5.1 的关系。
- **版本**：按缩窄版支持 minor；B 若裁"阻止合并"而未接线，另开实施票（§6.6③④）。

最终取舍由主持人与维护者裁定。
