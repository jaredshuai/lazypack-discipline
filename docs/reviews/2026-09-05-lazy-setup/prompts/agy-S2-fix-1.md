## 修复清单与回归要求

### F01 安装与门禁状态：对应 P0-1

在 SKILL 执行流程明确：确认中列出安装动作、预计文件变更和成功/失败的条件分支；确认后实际执行已批准的安装，再核验命令可调用，最后按真实结果渲染和接线。接受推荐、返回退出码零、检查结果通过是不同状态。
安装失败写 install-failed 并报告，不能先写 wired 后假定一定成功；未获确认或超出计划的安装不得执行。网络失败后的重试不能无限重跑，更不能追加未确认工具。
用新根内受控的安装成功/失败替身验证状态流；明确这只是流程演练，不是 npm/uv 真实安装成功证据。不要给主仓安装依赖。

### F02 Shell 隔离、失败保留与引用：对应 P0-2

每项命令在独立子 shell/进程执行并回收退出结果。命令里的 exit 0 只能结束当前项，不得跳过下一项；命令不能通过修改 EXIT_CODE 清除父进程失败记录。非法状态、遗留状态占位符和 wired 空命令应显式失败，不能默认跳过。
把命令作为数据安全赋值/传参，写清完整转义规则和渲染方法；引号、美元符号、反引号、反斜线或换行不得在赋值阶段执行。命令本身获授权后执行与赋值意外执行要区分。
回归必须直接渲染并执行产品 pre-commit.sh 模板，不另写替代门禁实现。覆盖：missing 后的 wired 确实运行；exit 0 后下一项确实运行；先失败再成功或尝试改父变量仍失败；非法状态失败；含单双引号、空格、字面美元符号/命令替换的命令只在执行阶段按预期运行。断言退出码和可观测日志/本轮文件证据，不能只看 exit 0。

### F03 无基线冲突：对应 P0-3

删除无基线情况下的 3-way diff 承诺。CONFLICT 展示磁盘当前正文与拟生成正文的 2-way diff，说明同时存在人工修改和输入/模板变化；用户可保留现状、采用候选或自行合并。不要从哈希猜基线，也不要为此新增旧模板库、独立状态系统。
验证在仅有现状及摘要的场景，产品指令不要求虚构第三份文本；静态核对与实际会话演练分开记录。

### F04 离线来源：对应 P1-1

移除五份模板中未经验证的 owner/tag 在线 URL。改为可追溯的固定层版本、内容标识及已安装 lazypack-setup/references/DECISIONS.md 的解析说明；agent 从当前 skill 资源根定位，跨设备不依赖作者机器绝对路径。目标仓不复制整份规则。
原上游内容标识可实算，不能盲目写死审查中的示例。匹配的 skill/快照版本不可读时诚实报告，不随便拿最新版当旧版本。在线链接如保留，只作已核实的可选参考，不谎称它是离线快照。
验证本地可读资源、快照一致和模板不存在虚构 tag 指针；未做真正隔网会话就不要报端到端离线通过。

### F05 条件化指针：对应 P1-2

常驻入口四条项目文档链接改为条件渲染，SKILL 中给出明确规则。PAUSE/BROKEN/未生成对应产物时省略其指针，报告未托管；其余已准备的指针仍保留，不阻断入口自身。在计算 fp 前完成条件渲染；不能遗留占位符。
直接以产品 resident-entry.md 模板演练：一份、数份及全部文档暂停；确认正文和链接与预期相符。模拟渲染不等于真实 skill 会话。

### F06 管理器和真实激活证据：对应 P1-3

探测实际管理器、实际有效 hooksPath 及入口。无常见管理器不等于没有自定义 hook；不能无条件改成 .githooks。已有自定义路径在整体计划里明确兼容方式，无法安全判断则暂停这项。
把静态 configured 与 Git 原生调用 runtime-verified 分开；运行返回非零但有调用证据可以记录已被调用，同时检查失败，不能称检查通过。Husky/lefthook 不能套用硬编码 .githooks 的路径条件。没有 runtime 验证就标未验证。
在新验证根内用 git hook run 演练成功/失败和自定义 hooksPath，记录 Git 实际调用的命令、退出结果、独立可观测证据。禁止用 git add/commit 来验证，禁止读取/改写真实仓 hooks 配置。

### F07 换行和块外字节：对应 P1-4

规范化仅用于提取/哈希的内存副本。新独立文件可 LF；修改已有文件只替换确认的字节范围，新托管内容沿用适当的原换行。块外 CRLF、BOM、空白、尾部无换行等原样保留；不能先读取整文件转 LF 再整体写回。
回归取真实模板文本插入构造的 CRLF、LF、BOM、无末尾换行样本，断言原前缀/后缀 Buffer 相等、fp 跨换行一致。混合换行无法可靠推断时不得借此重写块外内容。

### F08 前置与 gen：对应 P2

有效 tracker 依可读的实际跟踪方式正文判断，不依赖固定英文/中文关键词白名单；标题或占位模板不算有效，纯中文实质说明应可用。Agent skills 的 tracker 链接必须位于该标题块作用域内，不是全文出现即可。
验证真实模板目录的 gen 计算、文件顺序、正文变化；不要用固定假 gen 冒充目录验证。测试前置判断可有演练辅助函数，但报告要明确它不是产品运行代码；不要为了让测试可导入而把 prompt skill 改造成新 CLI。
