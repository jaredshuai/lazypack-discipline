## 计票方式

这是本次会议的收票格式，不是对 §9 的修订。沿用访谈 Q23 多数制和 §9 三轮、奇数参与者、僵局维护者裁决：A/B/C 各一票，主持人不投。

- 每题只能选一个列出的选项，或填“弃权”并给原因；YES/NO 题不能自创“有条件赞成”。
- 同一选项获得至少两位明确支持才记为多数。弃权、缺票、赞成但要求改正文均不并入支持票。
- 任一题无人获得两票，或多数结果之间出现依赖冲突，交维护者裁决。不会以默认票、主持人偏好或沉默补足多数。
- 选项内容被误引/不可执行时，可以投 NO 或弃权，并在“阻断项”列说明；第三轮可以修订自己的论证，但附带新文字不会偷换本选项正文，也不会被记为对新文字的多数支持。
- NO 或延后不等于确认相反设计；未决部分保持现行规则。所有固定层补丁只有完整文本通过后才能执行。
- 计票规则如被参与者认为与现行章程冲突，应明确报告；主持人不得靠本格式自行修改章程。

## V08 托管区重跑机制（FINGERPRINT / REGENERATE / NO）

共同约束：固定一种标记语法，保留块外人工内容；块内有差异不静默覆盖。源/模板/项目命令变化都纳入检查；版本戳本身不能证明未手改。

- **FINGERPRINT：** 在托管区记录生成版本与内容指纹，先核对磁盘内容与写入记录，再区分未变、升级、drift。无可信旧基线或标记损坏时提示，不猜归属。来源：A D02、A 文中的 B-07-r2；C D02/C-02-r2。
- **REGENERATE：** 块头记源版本与模板内容标识；以当前模板和探测结果重新生成并比对，相同 no-op，不同统一展示差异等待确认，不判断谁改了。缺损标记视为不可信区域。来源：B B-06-r2/B-07-r2。
- **NO：** 两套机制仍不充分。

验收：同输入连续两次 no-op，块内手改不丢，块外字节不变，项目命令改变但源版本相同仍能发现。投 FINGERPRINT 须确认记录位置/哈希范围，投 REGENERATE 须解释如何达到稳定重生成；不得把尚未实测的验收说成已通过。

## V10 脏目标预检（PRECISE / CLEAN / WARN / NO）

- **PRECISE：** 不因工作区脏而强制停，只精确修改已确认清单，保护既有改动。来源：A D04。
- **CLEAN：** 无关脏文件不影响，但本次要修改的既有路径须干净，否则停止该写入并说明，不自动清理。来源：B B-04-r2。
- **WARN：** 预检本次目标，存在冲突风险即告警，由用户主导处理。来源：C D04。
- **NO：** 均不足。

验收包含已暂存修改、未暂存修改和无关未跟踪文件。CLEAN 不隐含允许丢弃已暂存内容。

## V11 中断恢复（REPORT / GIT / NO）

共同文字：先处理新建产物，再修改既有入口；不宣称多文件原子写入，不自动清理用户工作区。中断后逐项核对已写/未写/损坏状态，再按 V08/V09 重跑。

- **REPORT：** 失败报告列精确路径与差异；新文件和既有修改分开说明恢复办法，不用无条件 checkout 代替保护用户改动。来源：A D04/D04-r2，吸收 B/C 的先新后改顺序。
- **GIT：** 限 CLEAN 前提，用 Git 恢复既有路径，另列本次新建文件的删除清单；报告明确适用条件，不用 git clean。来源：B B-17-r2，依赖 V10=CLEAN。
- **NO：** 两者仍不可执行。

验收：模拟第三个产物处中断，能报告残留并安全补齐；新文件、索引中内容、后续人工改动、本地 hook/config 变化均不能被遗漏。原报告的 rm/checkout 示例不自动视为已验证命令。

## V12 hook 放置（TRACKED / LOCAL / EITHER / NO）

- **TRACKED：** 沿用已有 hook 管理器和版本控制内入口；缺管理器时生成受版本控制的门禁脚本并显式说明本地 hooksPath 接线。不能把文件存在视为本机或新克隆自动激活。来源：B B-11-r2、§1.3。
- **LOCAL：** 有现成管理器则追加其入口；否则原生 .git/hooks/pre-commit 接现有命令。来源：C D03；本机激活与其他机器重装限制必须如实报告。
- **EITHER：** 保持项目层选择，可使用已有管理器或原生 hook，不统一限定存放位置。来源：A D07/A-09-r2。
- **NO：** 均不足。

验收：保留已有 hook 行为、四项命令可追溯、不同设备启用方式明确。所有 Git 配置写入计入 V05 整体确认清单；这只是说明既有授权边界，不额外创造产品确认步骤。

- **A：** 分开报告 setup 过程结束与门禁生效；区分已接线、未接线、不适用、安装/运行失败，未实跑不称已验证，不要求 setup 为结束流程必须跑满套检查。来源：A D03/A-09-r2。

来源：A A-13-r2/§5；B B-15-r2/D08/§5.3；C D08/§5.2；现行 §3。

验收最少包含：缺前置零写入、常见少问、重跑 no-op、块内/块外人工修改、命令变化、标记损坏、部分写入恢复、已有 hook、门禁缺失与失败、来源版本可读。选中的技术机制仍需在规格阶段写清可执行边界，不能跳过阻断项直接派实现。
