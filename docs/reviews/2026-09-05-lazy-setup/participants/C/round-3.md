## 对第二轮自案的最终修订

立足对抗性运维者视角，对第二轮自案进行严肃自省与必要修正：
1. **修正 V04 提问硬上限**：从第一/二轮坚持的“至多两题（TWO）”硬上限修正为“**NEEDED**”。硬上限在真实复杂仓库遭遇必要未知时会逼迫 AI 盲猜或瘫痪，违背 §7.5/§7.6（不猜测、如实报告）。优化目标仍为 0 问，但真实未知必须附带理由如实提问。
2. **修正 V12 hook 存放位置**：放弃第一/二轮主张的“本地原生 `.git/hooks/`（LOCAL）”，转为支持“**TRACKED**”。`.git/hooks/` 不受版本控制，存在跨设备克隆丢失、无法提交给审查者审查 diff 以及与既有 husky 冲突的致命缺陷；hook 入口必须受版本控制跟踪。
3. **修正 V17 跨设备约束范围**：放弃在第二轮中试图通过“项目操作指引”引入强制 fetch/rebase（GUIDE）的折中做法，转为支持“**DEFER**”。首版聚焦 setup 编译本身，跨设备协作机制另立专项，不通过非固定层文本夹带未充分验证的操作硬约束。
4. **修正恢复与回滚语义**：撤回第二轮示例中无条件 `git checkout --` / `git restore` 的粗暴写法。由于未跟踪新建文件无法被 checkout 清除，且已有脏文件会被 checkout 抹杀未提交修改，全面倒向“只要求待修改路径 CLEAN 前提 + 新建文件输出确切 rm 清单 + 既有文件通过托管标记与 REPORT 指引恢复”。
