## 对第二轮自案的最终修订

本轮我撤回或修订了七处自己的立场，全部因论证而非凑票。撤回项如下（保留项见投票表）：

1. **B-06-r2 / B-07-r2（REGENERATE）→ 撤回，改投 V08=FINGERPRINT。** 摘要第 2 条的质疑成立：重生成的稳定性取决于「模板只做字面替换、不含任何由 AI 组织的散文」，而 `skills/` 目前为空，这个前提在模板存在前**无法验证**；一旦模板含散文，每次重跑都产生虚假差异，机制退化为「永远要问」，同时毁掉 lazy 与 no-op。更实质的损失是：REGENERATE 无法区分「模板变了」与「用户手改了」，因此**干净升级也必须弹确认**。FINGERPRINT 把指纹记在块头注释里，既满足我第一轮坚持的「零新增元数据文件」，又是纯字符串比对、不依赖 AI 输出稳定性，还能让「指纹相符 + 版本落后」直接就地升级而不打扰用户。记录位置与哈希范围见阻断项 B1。
2. **B-17-r2（V11=GIT）→ 撤回，改投 REPORT。** 我的 `git checkout --` 恢复有三个未闭合前提：① 「干净」未区分已暂存与未暂存（`checkout --` 从索引恢复，语义随暂存态变化）；② 回滚命令只在写入后**立即**有效，用户事后再改该文件时执行它会毁掉新工作，我第二轮未给有效窗口；③ `.git/` 内文件与 `core.hooksPath` 等 git config 变更**根本不在 git 恢复范围内**，基于 checkout 的回滚会静默漏掉它们——而这正是 V12 会产生的改动。另外 GIT 依赖 V10=CLEAN，投它会给计票制造依赖冲突。
3. **B-04-r2（V10=CLEAN）→ 撤回，改投 PRECISE。** CLEAN 的硬停是为了让 `git checkout --` 成立；既然放弃该恢复机制，硬停就只剩代价。我们的写入是标记区内追加，按构造不触碰既有行，加上 V05 的整体差异预览，「保护既有改动」已经成立，不需要额外的停止点。
4. **B-19-r2 中「`wired` 即可称已生效」→ 撤回该等式，改投 V14=A。** 摘要第 3 条与 V14 的提示都对：命令执行 ≠ hook 激活 ≠ 检查通过。hook 可以写对却不生效（husky 未初始化、`core.hooksPath` 未设、缺可执行位、新克隆未装依赖）。我第二轮把「本次实际执行过一次」当作生效证据，是以命令可用性冒充门禁有效性。我的四态词汇在 A 正文中已完整存在（「已接线、未接线、不适用、安装/运行失败」），且 A 还区分了运行失败与安装失败，故改投 A 不丢任何东西。
5. **B-11-r2 的条文文本 → 撤回，改投 V15=A。** A round-2:18 对我第一轮因果链的反驳是对的（6.1 说的是「提交前 hook」不是 Husky；无 `package.json` 推不出装不了 Git hook），我第二轮已改口为「有可跑门禁命令」，但**我的文本仍有独立缺陷**：「否则把门禁命令记入 `RELEASE.md`」在根本没有命令可记时不成立，等于把「写进 RELEASE」当成装完，正是 A 指出的逃逸口。A 的文本把例外挂在**证据**上（能接到命令则写出；否则标明未接线或不适用及原因，不得宣称已生效）而非挂在仓库类型上，且不削弱 6.1。C 的文本则把「无 hook 安装条件的仓库」这一已被双方驳倒的前提写进固定层，不可投。
6. **B-12-r2（修订 §1.3）→ 撤回，改投 V07=SKILL。** 若 V06=B 通过，我的两个歧义分支变为不可达：常驻文件双缺失时 Matt 的入口块也不存在，V06 会先停机，lazypack 根本走不到「选哪个文件」。既然不可达，就不必为它开 §9、升版本。另有一个我第二轮没说清的理由：把「优先 CLAUDE.md」写进固定层，等于把 Matt **当前实现细节**钉进条文，与 :26「角色到 skill 的映射是可换的适配层，不强绑」的反耦合原则相悖。§1.3 在双存在情形是**沉默**而非矛盾，规格补足即可。
7. **B-16-r2（V18=NPM 的 npm 专属实测门槛）→ 撤回该门槛，改投 THIN。** 「npm 段须有本地可执行验收」有被读成授权发布副作用的风险（选票末行已声明不授权发布）；而平台段的**机制**（探测 → 薄草稿 → 标注）由「无平台」这一取值就能完整验到，不需要绑定某个厂商的发布流。我保留的实质要求由 THIN 与 V19 承接：未验证内容必须标注、三场景各有可执行验收。
8. **第二轮采纳 A-09「只接已有命令」→ 修订，改投 V13=RECOMMEND。** :87 原文已给 JS/TS 与 Python 的默认工具，并明写「其他语言由 `/lazypack-setup` 问」——所以推荐默认工具是**执行**固定层，不是越权。CONNECT 会让一个全新 TS 仓在 :87 明明有默认工具的情况下零门禁收场，反而不满足 6.1。且 `install-failed` 这一态（我的四态与 V14=A 都含）在 CONNECT 下不可达，属内部不一致。RECOMMEND 首句仍是「优先继承已有命令」，我关心的老项目保护没有损失。
