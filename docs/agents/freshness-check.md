# 本仓文档防腐检查（开工与收尾）

本文件是维护 lazypack-discipline 本仓时，开工识别核对范围、收尾留下检查记录的流程正文。文档关系声明的唯一正文是 [doc-pairs.md](doc-pairs.md)。本文件不复述那些声明，不新建角色，不修改固定层。

本流程只约束本仓。其他仓库的声明和流程由该仓库的项目层自己写，不从本文件继承这六条对子。

Agent 接到本仓任务后按本文件执行，不必等用户提醒「记得改文档」。流程已经写明，只说明本仓维护时要做这件事。`node scripts/check_doc_pairs.mjs` 仍须手动运行，未接 hook 或 CI，不表示日常自动维护已经交付。

## 1. 开工：识别要核对的内容

改文件之前先做这四步：

1. **任务。** 读本轮目标和硬约束，包括点名的文件和明确不做的事。
2. **实际差异。** 看开工时已经存在的 diff，以及本轮准备修改的路径。提交标题只作线索。
3. **登记册。** 按 [ARTIFACTS.md](../ARTIFACTS.md) 的归属表确认这些路径的权威正文和更新触发。同一内容只改权威位置。
4. **声明。** 打开 [doc-pairs.md](doc-pairs.md) 的 `## 声明`。来源或目标范围里的路径出现在任务点名或实际差异中，就把该编号列入机器检查。本轮改了声明文件或 `scripts/check_doc_pairs.mjs` 时，列入全部已声明编号。任务写明不动某份来源（例如固定层）时，也列入对应编号，用来确认它没有变化。

然后分成三栏，留到收尾记录：

- 将运行的声明编号
- 机器检查覆盖不了、需要阅读的语义问题：目标有没有被写成已经交付，历史记录有没有被改写，有没有出现新的决策
- 未覆盖范围：没有声明的关系、本票明确不做的能力、不在本轮授权内的仓库

未覆盖保持可见，不算通过。本流程不调用「任意代码 diff 到任意文档段落」的定位器。没有这种工具时，语义影响标为人工阅读或未覆盖，不编造定位结果。

改声明正文的顺序以 [doc-pairs.md](doc-pairs.md) 的「何时运行」为准。

## 2. 按声明里的处理权限行事

每条声明的处理权限只以该条字段为准。本文件不另写权限表。

- 字段写明只读报告时，运行检查并记录结果。发现差异就记失败。不靠改写来源或目标让检查变绿，除非本轮任务另外授权。
- 内容能确定，且本轮授权覆盖该目标范围时，只改权威位置，并同步登记册里指向它的入口。
- 有疑问、证据不足，或与有效需求、ADR、规则冲突时，保留原文和冲突，写入未决，交回用户。
- 新的产品或纪律决策交回用户。历史验收和来源材料保持当时的记录。

## 3. 收尾记录

把下面五项写进 `docs/ARTIFACTS.md` 的当轮说明。命令原文或长输出放系统临时目录，并用 `scripts/handoff_manifest.js` 为仓库内载荷生成同源清单。登记册不手抄清单哈希。

1. **检查范围。** 实际跑过的声明编号，以及人工看过的语义问题。没跑的编号不要写进已核对。
2. **依据版本。** 开工时的提交；收尾核对时的提交，尚未提交就写工作区。再加上声明文件路径和检查器命令。
3. **处理结果。** 每一项只用下面一个词。
   - `未发现差异`：检查已经运行，该检查方式下来源与目标一致。检查器该条为 `PASS`，且同一行没有 `declaration=`。
   - `已同步`：发现差异，并在该条处理权限和本轮授权内改了唯一权威位置。
   - `失败`：检查已经运行且未通过，或应该同步但没有完成。同一行即使有 `check=PASS`，只要有 `declaration=`，整条仍是失败。
   - `未运行`：本应执行但没有执行，写明原因。
   - `缺基线`：没有可对照的来源、目标或版本，例如文件读不到，或 git 给不出 blob。不能解释成没有差异。
4. **未覆盖范围。**
5. **未决事项。**

失败、未运行、缺基线不得写成已核验或未发现差异。检查器退出码非零时，整次机器检查不是通过。

声明节读失败（摘要为 `error=未找到标题`）时，内容对照没有执行。这记为失败：检查器已经运行，但不是缺基线，也不是未运行。

## 4. 命令

在仓库根运行：

```bash
node scripts/check_doc_pairs.mjs
```

运行前后用 `git status` 确认检查器没有改仓库。本命令未接 hook 或 CI。

## 5. 本仓边界

要把确定性检查接入门禁，须另有实施票写明范围和授权。本文件不授权接入 hook、CI、定时任务，也不授权自动提交、自动批准、自动合并或安装外部文档生成器。
