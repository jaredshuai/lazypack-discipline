# ADR 001：以可复用模板和标准装配为主要可靠性投入

日期：2026-10-18。状态：`current`（产品路线决策）。现行产品政策见 [VISION.md](../VISION.md)；文档归属与本决策登记见 [ARTIFACTS.md §3](../ARTIFACTS.md#3-已核对的入口登记)。

## 背景

旧仓结构和自动审查意见可以持续产生新的适配需求。逐个消除特例，会让兼容分支、规则和测试成本持续增长，偏离建设可反复使用的工程模板这一目的。原 VISION 的“先完善纪律自动化，再扩展模板组合”路线也容易让可靠模板的积累无限后置。

维护者在 [Issue #94](https://github.com/jaredshuai/lazypack-discipline/issues/94) 明确模板优先方向，经多 AI 讨论与 [Astra 裁决](https://github.com/jaredshuai/lazypack-discipline/issues/94#issuecomment-6247753464) 收束，并在本轮授权实施。可靠性投入会长期影响产品架构与维护成本；不记录背景容易把有限支持误读为忽略缺陷，而两种路线确有取舍，因此单独记录本决策。

## 决策与替代关系

以官方模板和声明支持的标准装配作为主要可靠性投入，取代上述“先完善纪律自动化，再扩展模板组合”的先后路线。具体责任边界统一由 VISION 维护，本 ADR 只保留此次选择的缘由。

保留已合入成果、Matt skills 复用、按需轻量装配及已有用户收益目标；本次没有修改固定层或分发给目标项目的模板。既有行为的缺陷责任与扩大支持范围的投入决定分开处理。

## 放弃的选项

- 把任意历史代码库完全自动化改造作为默认目标：支持范围不可控，会持续增加模板以外的维护成本。
- 把每条 Bot 建议都转换为必须消除的问题：审查意见不能替代产品投入裁定。
- 用尚未验收或非标准场景豁免既有保护责任：会损害用户已有工作，也混淆承诺与证据。

## 接受的代价

部分历史结构需要人工处理、单独裁定或暂不支持，无法保证每个项目都能自动装配成功。维护者需要对真正的支持扩展作取舍，承诺冲突也需要明确澄清；这些代价换取可控、可重复验证的模板建设。后续验证仍须如实说明环境和范围，本决策本身不证明任何新增能力已经交付。
