# 跨阶段交接同源清单与核验指引 (handoff-verification.md)

本指引规范多 Agent 在跨阶段任务（如需求规划、代码落地、本地提交、版本发布等）中的产物交付与核验流程，确保交接报告中的文件摘要与磁盘物理实物完全一致。

---

## 1. 原则与背景

- **单一事实源与推导一致性**: 严格遵循 [DECISIONS.md §4.1](DECISIONS.md)“能推出来的不手写”与 [§7.5](DECISIONS.md)“交接只写亲自验证过的事实”。交付报告中的文件大小、哈希和换行类型必须由统一工具同源采样生成，杜绝任何人工二次转录或独立脚本差异。
- **物理实物为第一权威**: 默认哈希均为文件在磁盘上的原始字节 SHA256（`sha256_raw`）；LF 规范化哈希（`sha256_lf_normalized`）仅在显式要求下作为辅助字段提供，二者严禁混淆。
- **零依赖与可重现**: 核心工具 `scripts/handoff_manifest.js` 基于纯 Node.js 标准库构建，无需安装第三方依赖，开箱即用。

---

## 2. 工具调用方式

### 2.1 交付方：同源生成清单与摘要表 (`generate`)

```bash
node scripts/handoff_manifest.js generate \
  --root <工作区基准根目录> \
  --files-json <显式相对路径字符串数组JSON文件> \
  --out-dir <尚不存在的新交付目录> \
  [--include-lf-normalized]
```

- `--root`: 待测文件的基准根目录（如当前仓库根目录或目标工作区）。
- `--files-json`: 包含显式相对路径字符串数组的 JSON 文件绝对或相对路径。不支持通配符隐式遍历，必须显式指定。
- `--out-dir`: 本次交接产物的目标输出目录。**必须为一个尚不存在的新目录**；若目标已存在，工具强制拒绝执行以保护历史归档。
- `--include-lf-normalized`（可选）: 仅在所有输入文件均为合法的 UTF-8 文本时可用。会将 `\r\n` 规范化为 `\n` 后计算辅助哈希，遇二进制或非法 UTF-8 会明确阻断。

**输出物**:
在指定的 `--out-dir` 下原子生成：
1. `manifest.json`: 机器可读的结构化清单（包含 `schema_version`、`generated_at`、`files_count` 及 `files` 数组）；
2. `table.md`: 由完全相同的内存数据渲染出的 Markdown 摘要表，供交接报告直接引用或嵌入。

### 2.2 接收方：不可信清单反向核验 (`verify`)

```bash
node scripts/handoff_manifest.js verify \
  --root <工作区基准根目录> \
  --manifest <manifest.json 路径> \
  [--table <table.md 路径>]
```

- `--manifest`: 待核验的机器清单。工具将其视为不可信输入，首先严格检查其 JSON 语法、Schema 结构、字段类型与文件计数。
- `--root`: 待校验的工作区根目录。工具依据清单逐一重读磁盘物理文件，核验大小、`sha256_raw` 及可选的 `sha256_lf_normalized`。
- `--table`（可选）: 若提供，工具使用生产相同的纯渲染逻辑重新渲染预期 Markdown 表格，并与该文件进行逐字节比对，防止表格被手工篡改。

## 3. 标准交接执行时序

跨阶段工单的标准交付与验收管道如下：

```
[交付方准备显式文件清单 input-files.json]
                 ↓
[执行 generate 命令]
  ├── 步骤 1：物理采样输入文件（原始大小、sha256_raw、探测换行类型）
  ├── 步骤 2：在内存中组装 manifest 并同源渲染 Markdown table
  ├── 步骤 3：在目标父目录下创建独占的临时 staging 目录并落盘
  ├── 步骤 4：交付前重新读取所有输入文件，对比大小与哈希（探测并发修改）
  ├── 步骤 5：读取 staging 产物确认无损坏
  └── 步骤 6：确认目标 out-dir 仍不存在，将 staging 目录原子重命名至 out-dir
                 ↓
[编写交付报告 result.md]
  └── 直接嵌入或引用生成的 table.md，报告自身不参与文件清单
                 ↓
[接收方验收]
  └── 执行 verify 命令，通过退出码 0 与详细比对报告确认交付实物一致
```

## 4. 边界规则与安全约束

1. **输入文件严格只读**: 工具对输入文件仅开启只读文件流，严禁修改、重命名或暂存被测源码。
2. **禁止整仓通配与敏感路径**:
   - 必须通过 `--files-json` 提供显式文件清单，杜绝隐式通配符递归；
   - 严格禁止访问 `.git/`、`node_modules/` 路径（`generate` 与 `verify` 均强制拦截，并在任何磁盘访问前安全阻断）；
   - 自动拦截明确的密钥/凭据文件（如 `.env`、`*.pem`、`*.key`、`id_rsa` 等）。
3. **输出目录要求与防覆写**:
   - `--out-dir` 必须显式指定且尚不存在，其父目录必须存在；
   - `--out-dir` 可以位于工作区根目录内或根目录外，但绝不得与任何输入载荷文件发生路径重叠；日常工单交接推荐约定为系统临时目录（如系统 TEMP），以保持源码树整洁；
   - 若目标 `--out-dir` 已存在，工具立即报错中止，严禁静默覆写或删除旧目录。
4. **自引用与载荷隔离**:
   - 清单与摘要表仅记录本次交付的目标载荷文件（Payload Files）；
   - 工具仅依据实际路径关系严格拒绝 `--out-dir` 与输入待测载荷的重叠；
   - 调用方负责在工单交接中自行排除正在编写的承载报告（如 `result.md`），工具未获得该报告路径时不谎称能自动感知，亦不增加任何基于文件名（如 `result.md`）的黑名单猜测；
   - 交付报告只需直接引用或嵌入生成的 `table.md`，无需手工回填自身哈希。
5. **去敏要求**:
   - 清单与表格中仅记录统一的正斜杠相对路径（如 `docs/foo.md`），绝不输出本地绝对路径或敏感用户名；
   - 相对路径本身若含有敏感命名，由调用方在提供清单前自行泛化，工具不自动证明业务语义脱敏。
6. **相对路径表格渲染安全**:
   - 摘要表中的普通相对路径默认采用 CommonMark 规范行内代码围栏，安全转义独立管道符（`\|`），并通过动态反引号围栏与空格填充保障反引号与尖括号原样展示；
   - 针对反斜杠紧邻管道（`\+|`）的特殊边界，采用固定 `<code>` 容器结合 Unicode 码点数字字符引用（NCR）整体纯文本编码，杜绝表格列被意外拆分、Markdown 内联语法干扰与 HTML 节点注入，确保渲染后可见文本与原路径严格 100% 往返保真。

---

## 5. 局限性与证据效力声明

> [!WARNING]
> **并发竞态客观局限**
> 静态文件哈希仅对工具执行采样与重读时的磁盘快照有效。由于操作系统文件系统并非单会话独占，工具无法保证采样之后没有其他进程发起并发修改。交付证据代表的是特定时间戳下的静态物理基准。

> [!NOTE]
> **人工定性结论不受哈希担保**
> 本工具校验仅能证明“某相对路径的文件在特定时刻具备特定字节数与物理哈希”这一物理事实。交接报告中由人类或 Agent 撰写的主观分析、测试充分性评价或质量判断，均属于人工定性结论，不受摘要表校验的自动担保。
