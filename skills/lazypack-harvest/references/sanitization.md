# 深度脱敏规范与数据边界（references/sanitization.md）

本文档定义 `/lazypack-harvest` 的脱敏规则、敏感片段处理策略与安全边界，依据冻结规格 `SPEC.md` §1.2 及 §2 阶段 4。

---

## 1. 强制脱敏覆盖范围与前置要求

脱敏处理必须在**向任何外部接口或只读查询发出网络请求之前**完成：
1. **Issue 标题**：去除项目特定名称、企业缩写、机器标识。
2. **Issue 正文**：五要素正文全面脱敏，尤其是“观察到的疼”与“证据摘要”。
3. **公开标记（Labels/Tags）**：严禁将业务代码或企业标识带入标签。
4. **查重与检索查询串**：在执行 GitHub Search 等查重查询前，必须由**已泛化、脱敏后的抽象概念**构造查询串，**严禁将原始敏感会话明文或未脱敏凭据直接作为查询参数发送给远端接口**。

---

## 2. 脱敏置换字典与范式

| 敏感类型 | 示例特征 | 安全置换占位符 |
|---|---|---|
| **Windows 绝对路径** | `C:\Projects\Secret\...` | `<DIR/PATH>` |
| **Unix / Mac 绝对路径** | `/home/user/repo/...`、`/Users/...` | `<DIR/PATH>` |
| **云服务与凭据密钥** | `AKIA[0-9A-Za-z_]{8,}`、`ghp_...`、Bearer Token | `<REDACTED_API_KEY>` / `<REDACTED_TOKEN>` |
| **内部私有包与命名空间** | `@fintech-internal/auth` | `<REDACTED_INTERNAL_PACKAGE>` |
| **邮箱地址** | `developer@corp.domain.com` | `<REDACTED_EMAIL>` |
| **内部 IP 与私有域名** | `10.x.x.x`、`192.168.x.x` | `<REDACTED_IP>` |
| **企业或客户项目专有名词** | 企业项目代码、商业系统名 | 泛化为技术栈类型（如 "TypeScript 后端微服务"） |

## 3. 边界反例处置规范

### 3.1 仅含敏感片段、无纪律议题（Scenario 7 / T18）
- **现象**：会话日志仅出现敏感路径、AKIA 密钥或私有包名；用户未指出哪条工程纪律受阻，也未提出未撤回改进提议；无门禁执行报错。
- **判定责任**：**由宿主 agent 审视当前会话可见事实与用户最终意图判定**。
  - **重要原则**：**无关键词不代表无候选，包含“门禁”二字不代表有候选**。严禁使用简单的关键词词表或正则规则代替完整的上下文语义理解。
- **处置原则**：**不立项、不生成候选、不向远端发起任何查询或创建网络请求**！
- **批次状态**：`NO_CANDIDATE`，干净退出。**严禁仅凭“成功脱敏敏感词”凭空捏造 Issue 候选**。

### 3.2 包含未撤回提议且带有敏感词（Scenario 7b / T18b）
- **现象**：用户明确提出纪律改进提议（例如提议项目层补充凭据提交指引），同时会话上下文出现了敏感路径或密钥。
- **处置原则**：按用户未撤回的提议立项，经过深度脱敏后发布。
- **严正禁令**：**严禁编造门禁扫描语法解析冲突！** 若环境中无门禁报错，疼和证据中必须如实记录“无执行报错，用户自述卡在流程规范”，绝不无中生有。

## 4. 客观声明（诚实边界与 Helper 辅助信号定位）

1. **有限检查信号定位**：
   - 内置辅助脚本 `sanitize_helper.js` 仅提供已知正则表达式的模式匹配与替换；
   - 其审计接口 `verifySanitization` 返回的 `noKnownViolations = true`（或兼容别名 `safe: true`），**仅表明已知模式库未命中，绝不代表或证明该文本已被批准安全外发**！
   - 宿主 agent 必须履行最终责任，主动审查是否存在模式库未覆盖的项目专有名词、私有目录段、内部主机名以及组合识别信息。
2. **非万能去敏声明**：
   - 依据 DECISIONS.md §10.3 及规格要求：采用基于模式替换与语义泛化的脱敏策略，**不做出“100% 绝对无泄漏”的夸大断言**。
   - 若正文在脱敏后依然无法确保抹除专有凭据，前置检查应主动阻断，转入 `DEPENDENCY_BLOCKED` 并保存草稿留待人工复核。
