# 正文五要素模板与提交契约（references/body_template.md）

本文档定义 `/lazypack-harvest` 生成的标准 Issue 正文结构、目标仓库边界与分诊衔接规范。

---

## 1. 目标仓库与标签约束

- **目标仓库**：固定为公开仓 `jaredshuai/lazypack-discipline`。
- **标签要求**：必须携带且仅携带 `harvest` 标签。
  - 严禁擅自打上 `ready-for-agent`、`bug`、`feature` 等标签。
  - 当次运行时必须动态核验目标仓库是否存在 `harvest` 标签；若查询证实缺失或无法核验，严禁自动创建标签，立即转入 `DEPENDENCY_BLOCKED`。
- **状态流转契约**：
  - 本技能创建的 Issue 统一进入维护者 Matt 的 `triage` 分诊通道（`needs-triage` → `ready-for-agent`）。
  - 本技能仅为外部传感器，不越权裁决，不代替分诊。

---

## 2. Issue 标题规范

标题格式统一为：
```
[harvest] <精炼概括的核心摩擦问题或改进点>
```
- 标题必须先经过深度脱敏，严禁出现项目专有名称、机器路径、用户标识。
- 长度建议控制在 20–50 字，准确反映纪律痛点或未撤回提议。

---

## 3. 正文五要素结构（Markdown 模板）

Issue 正文必须严格包含以下 5 个二级章节，顺序不得颠倒：

```markdown
## 1. 来源项目类型
[说明来源项目的泛化架构类型、技术栈与运行形态。例如："Node.js + Biome CLI 工具" 或 "React + Vite SPA 内部系统"。严禁填写业务项目专有名词或企业内部代号。]

## 2. 会话日期
[会话发生的实际日期，格式为 YYYY-MM-DD。若会话日志中无法确证日期，如实填写 "未知"，严禁虚构。]

## 3. 观察到的疼（摩擦现象）
[如实描述在 AI 对话或工程执行中遇到的纪律执行摩擦、矛盾冲突、或用户未撤回的流程改进提议。
必须忠实于当前会话可见事实。若无终端执行报错，如实写明 "无执行报错，用户提出主观流程优化提议"。]

## 4. 建议改哪层哪条
[明确指出建议调整的纪律层级与具体条款。例如："固定层 §4.1 (交接文档存放位置)"、"项目层 凭据提交指引"、或 "待 Matt triage 分诊裁定"。]

## 5. 证据摘要
[摘录经深度脱敏后的关键日志片段、命令调用序列、报错摘要或用户未撤回提议原文。
严禁出现未脱敏的绝对路径、私有作用域包名、密钥凭据或内部邮箱。严禁为了凑证据而无中生有捏造门禁语法或扫描错误。]
```

---

## 4. 示例展示

```markdown
## 1. 来源项目类型
TypeScript CLI 工具（基于 Biome 与 Node.js 运行时）

## 2. 会话日期
2026-09-07

## 3. 观察到的疼（摩擦现象）
项目层未明确包含敏感配置时的提交规范，用户在多轮交互中持续困惑能否提交以及如何脱敏，最终提出在项目层补充凭据提交指引的提议。

## 4. 建议改哪层哪条
项目层 docs/DECISIONS.md 凭据提交指引 / 待 triage 评估

## 5. 证据摘要
- 用户提议记录：「项目层没写含凭据配置如何提交，卡在能不能交；请评估是否在项目层补一句指引。」
- 执行状态：无终端执行报错或门禁冲突；核心痛点为流程指引缺失。
```
